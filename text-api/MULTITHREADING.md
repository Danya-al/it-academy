# Практика по многопоточности

Консольные примеры находятся в пакете `ru.academy.textapi.multithreading`. Каждый класс с `main` можно запустить отдельно в IDE на Java 17. Для запросов из первого задания запусти приложение `text-api`.

## 1. Запуск потоков

`ThreadBasicsDemo` запускает два именованных потока. Один выводит `1–10`, другой `A–J`. Вызов `join()` после запуска обоих потоков гарантирует, что `Done` появится последним. Порядок строк каждого потока сохраняется, а их чередование может меняться.

Запусти класс с аргументом `--pause`, чтобы добавить паузу 100 мс между строками. `--subclass` запускает вывод букв через наследование от `Thread`. `--priorities` меняет приоритеты потоков. Приоритет не гарантирует порядок выполнения. Аргументы можно сочетать.

`ThreadLogController` запускает два потока, которые добавляют своё имя и номер итерации в синхронизированный список. `GET` возвращает снимок последнего запуска, в том числе пока потоки работают.

```text
POST /api/multithreading/runs?iterations=10&sleep=true&differentPriorities=true
GET  /api/multithreading/runs
```

`POST` принимает от 1 до 1000 итераций на поток и отвечает `202`. Пока текущий запуск выполняется, повторный запрос получает `409`. После завершения в снимке будет по одной записи на итерацию каждого потока, то есть 20 записей для приведённого запроса.

## 2. Гонка данных

В `RaceConditionDemo` десять потоков увеличивают общий `Counter`. Обычный `int` может потерять часть инкрементов, потому что `++` состоит из чтения, вычисления и записи. После `join()` версии с `synchronized` и `AtomicInteger` должны дать ровно 1 000 000. Если обычный счётчик случайно дал ту же сумму, запусти демонстрацию ещё раз.

## 3. Производитель и потребитель

`ProducerConsumerDemo` дважды передаёт строки через очередь. `BoundedTextQueue` удерживает ограничение размера: производитель ждёт свободного места, потребитель ждёт данные. Условия проверяются в `while` после пробуждения, а изменение очереди сопровождается `notifyAll()`. Затем те же строки проходят через `ArrayBlockingQueue`. Обе версии проверяют количество и порядок полученных строк.

## 4. Пакетная обработка текста

`BatchTextAnalyzer` отправляет задачи `Callable` в фиксированный пул. Результаты собираются из `Future` в порядке входных строк. Для каждой строки возвращается количество кодовых точек и слов, разделённых пробелами или другими пробельными символами. При истечении общего тайм-аута незавершённые задачи отменяются. Демонстрация проверяет результаты и путь с тайм-аутом.

## 5. Координация потоков

`ConcurrentStartDemo` через `CountDownLatch` ждёт готовности пяти потоков и даёт им общий сигнал старта. Ещё одна защёлка сообщает главному потоку, что рабочие потоки закончили. Каждый пишет длину своей строки в отдельную ячейку, поэтому итоги выводятся во входном порядке независимо от того, кто закончил первым.

## 6. Взаимная блокировка

Обычный запуск `LockOrderingDemo` показывает единый порядок захвата двух мониторов. Оба потока завершают обновление. Запуск с `--deadlock` специально меняет порядок во втором потоке. `ThreadMXBean` обнаруживает взаимную блокировку, а демонстрация завершает процесс, поскольку заблокированные потоки работают как daemon-потоки. Запускай этот режим отдельным Java-процессом.
